# Git 提交检查

检查本次拟提交的内容；只有用户要求提交时才执行提交。不要把本地文件删除，也不要仅凭 `.gitignore` 判断内容安全。

1. 用 `git status --short` 和 `git diff --cached --name-status` 确认已暂存、未暂存、未跟踪文件及本次提交范围。对准备加入提交的未跟踪文件也检查内容；不要顺手加入无关文件。
2. 审阅拟提交的差异。先筛查文件名，再用只输出路径、位置和类别的方式排查疑似秘密，避免在终端或聊天中输出原值。重点检查环境文件、配置、日志、私钥/证书、服务账号、令牌、密码、含凭据的连接串、个人信息和内部地址；区分真实值与示例占位符。不确定时标记为待确认。
3. 对发现的疑似敏感内容，只报告路径、行号或范围、类别及处理建议，不复述原值。将相关内容从本次提交中排除或改为安全占位符/环境变量后重查，并保留本地原文件。若凭据已进入 Git 历史，提示轮换或吊销。
4. 运行 `git diff --cached --check`，再次核对暂存区。报告“可提交”或“暂缓提交”、检查范围、问题及剩余风险；只有无未处理的敏感内容和无关文件时才继续用户要求的提交。

此 Skill 是审查流程，不替代 Git hook 或专用秘密扫描器。
